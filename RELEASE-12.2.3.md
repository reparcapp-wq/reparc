# RepArc 12.2.3 — fix historical completion labels blocking cloud saves

Root cause: the upload/backup validator used `sessionCountsAsCompletedDay` to reject any session labelled `completed` that no longer counted as a completed day. This blocked the entire profile when one historical label disagreed with stricter set-position rules. It also rejected completed deletion tombstones, because deleted sessions intentionally never count as completed days. The exact reported “Session 2 is marked complete but required sets are missing” error was reproduced with synthetic records before the fix.

Remove only that derived-completion upload gate. Structural, date, unit, numeric, size, owner-access and server-revision checks remain. Incomplete workouts, older completion labels and deleted-session history can be saved without inventing sets, deleting entries, changing historical labels, resurrecting tombstones or resetting pending changes. No production rows were manually edited.

Reports/adherence still calculate completion from actual prescribed set positions; extra sets do not replace a missing movement. Existing SBS replay checks still prevent a missing prescribed set from advancing that lift's training max. Recommendation formulas, calibration/return rules, load rounding and program templates are unchanged. No dependency or database migration changes.

Seven new regression cases cover historical Session 2 inconsistency, completed tombstones, legacy/partial/skipped sessions, backup restoration, continued rejection of genuinely invalid records, incomplete SBS work and retrying the original queued 422 failure through the client sync path. The retry test retains historical entries, labels, deletion markers, session revisions and a newly queued weigh-in. Five targeted history tests failed under the original validator and pass after this fix; the test of genuinely invalid records passes both before and after.
